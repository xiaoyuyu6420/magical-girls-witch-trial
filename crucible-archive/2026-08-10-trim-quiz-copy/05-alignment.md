# 05-alignment — 创意对齐产出

## 第 1 轮：复述 + 为什么

**用户目标**：精简题目文案，"不失去感觉"。
**真实动机**：当前题目文案铺陈过多（每题 80-150 字），阅读负担重，用户觉得"太多"。但调性（挑战者审讯体）是这个项目的灵魂/区分点，不能因为精简丢掉。

## 第 2 轮：完成边界

**成功的具象画面**：
- 用户答 26 题，每题读起来比现在轻快（少了冗余场景描写），但仍然感到被"审判/审讯"的压力
- "你……对吧？"句式仍在、省略号停顿仍在、二分悖论仍在——这些是调性的承重墙
- 总字数减少约 30%，但不是机械砍 30%，而是去掉每题里最可删的冗余部分

**失败的具象画面**：
- 精简后读起来像"普通人格测试题"（客观第三人称描述）—— 调性死了
- 评分/题型逻辑被破坏（score/dim/type/renderType 被误改）—— 行为变了
- 改了 quiz-content.ts 忘改 zh-CN.ts（或反之）—— 文案漂移

**反例（看起来像但不是）**：
- 只删字没保调性 —— 字数达标但感觉没了 ✗
- 只改一个文件 —— 字数达标但两份漂移 ✗
- 把所有题都改成同一句式 —— 单调，失去每题的独特切入角度 ✗

## 第 3 轮：约束发散

| 约束 | 用户确认 |
|------|---------|
| 评分逻辑不变（score/dim 不动） | ✓ 必须保持 |
| 题型不变（normal/scale/weight/gate/trigger 不动） | ✓ 必须保持 |
| 选项语义方向不变（选项A仍对应同一个分数档） | ✓ 必须保持 |
| 其他 locale 不动 | ✓ 只 zh-CN |
| 批注/prologue/结果标签不动 | ✓ |
| DB seed + 前端 fallback 同步 | ✓ 待确认渲染源后定实现方式 |

## 第 4 轮：期待 / 担忧

**期待**：精简后，答题体验更紧凑、节奏更快，但审判的压迫感不减反增（少了水分，刀刃更利）。
**担忧**：精简过度，变成了"又一个普通心理测试"，失去了"被审判"的独特感。

## 调性保护清单（精简时的红线）

以下元素是调性承重墙，精简时**必须保留**，只在万不得已时微调：
1. **第二人称"你"** + 审讯式直接对话
2. **"……对吧？" / "……对吗？"** 收尾句式（多数题用）
3. **省略号（……）** 制造停顿、心理试探
4. **破折号（——）** 语义转折
5. **二分悖论**（"你要么…要么…"、"不是…而是…"）
6. **挑战者人格化语气**（"别装了""别想了""承认吧"）
7. **选项三档结构**：反驳档（"不对"）+ 中间档（"我从不假装…"）+ 承认档（"……你说得对"）
8. **世界观关键词**：因子、侵蚀、残骸、魔女化、审判庭——这些设定词是沉浸感的来源，不能全删

## 精简手法（允许的操作）

- 删冗余场景铺陈（"你心里清楚那台仪器不会说谎" → 直接说结论）
- 删重复修饰（"已经在盘算" → "在盘算"）
- 合并同义句（两句话表达同一意思 → 留一句）
- 缩长定语（"那个宣读结果的机械女声" → "那个声音"）
- 保留骨架，只去水分
