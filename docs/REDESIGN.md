# 魔女审判 → 灵魂审判器：产品重构方案

> 本文档总结了 2026-08-07 的完整共创讨论，作为后续执行的指导方案。
> 这不是"答题流程优化"，而是一次**产品定位升级**：从"某个IP的人格测试"变成"跨IP的灵魂审判平台"。

---

## 〇、一图看懂：这次到底要做什么

```
之前：魔法少女的魔女审判（单一IP人格测试）
        题目：第三人称叙事 → 用户"扮演"角色
        维度：审判/侵蚀/羁绊/觉醒（带魔女味）
        结果：匹配 13+2 魔女审判角色

之后：灵魂审判器（跨IP灵魂匹配平台）
        题目：审判官灵魂拷问 → 用户"面对"自己
        维度：通用心理维度（IP无关）
        结果：跨IP匹配（魔女审判/小圆/...）"你 = 某角色"
```

**核心转变**：题目从"替角色做决定"（扮演）变成"被审判官逼视自己"（面对）。这个心理指向的翻转，是一切改动的出发点。

---

## 一、痛点的真正根因（讨论回顾）

### 表面症状
用户做到第10题左右失去耐心，觉得"没新意"。

### 最初误判（已被推翻）
- ~~流程太长~~ → 总时长其实不是主因
- ~~交互太单一~~ → 是症状之一，不是根因
- ~~缺乏中途反馈~~ → 是症状之一，不是根因

### 真正根因
**题目让用户进入"替角色做决定"的扮演模式，而非"被逼视自己"的面对模式。**

对比 MBTI 为什么火：MBTI 每道题都指向用户本人（"你是否经常觉得自己不如别人"），用户答题时是在**审视真实的自己**，这个"看自己"的动作本身就是投入感来源。

而原项目的题目是第三人称叙事（"你被带入地下室……你会"），用户答题时是在**替一个虚构角色做决定**，是游戏化代入，不是自我审视。场景写得再好，用户心里始终是"如果她遇到这个情况"，而不是"如果是我"。

**这才是"感觉不到在描述我自己"的真正含义。**

---

## 二、题目层：审判官灵魂拷问模式（核心）

### 心理指向翻转

| | 扮演模式（现状） | 面对模式（目标） |
|---|---|---|
| 题干 | 第三人称场景叙述 | 审判官对"你"的直接逼问 |
| 选项 | 角色的反应台词 | 你被迫承认/否认/狡辩的剖白 |
| 用户心理 | 我在替这个角色决定 | 我在被审判，必须面对自己 |

### 四个关键技法
1. **审判官作为逼视者出场**——不是NPC，是心理压力源，他的话直接指向用户本人。
2. **断言式逼问**——不说"你会怎么做"，说"你从来没有真正X过，对吧？"，用断言逼用户回应。
3. **选项是"承认/否认/狡辩"三态**——不是"选A还是B"，是"面对这个指控你怎么回应"。
4. **场景退为氛围**——监牢、因子等IP元素还在，但只是渲染压力的环境，不是叙事主体。

### 标杆样例（F1 复仇心，用户确认"很有感觉"）

```
审判官：「别装了。你嘴上说'放下了'，可你记得每一个伤害过你的
         人的脸，记得他们说过的每一句话，记得当时的天气。
         你从来没有真正原谅过任何人——对吗？」

  ┌─────────────────────────────────────────┐
  │ 不对。我是真的放下了。记着不代表没放下。   │  ← 否认
  └─────────────────────────────────────────┘
  ┌─────────────────────────────────────────┐
  │ ……你说得对。我只是假装放下了。            │  ← 承认
  └─────────────────────────────────────────┘
  ┌─────────────────────────────────────────┐
  │ 我从不假装。恨就是恨，我凭什么要原谅。     │  ← 狡辩（合理化）
  └─────────────────────────────────────────┘
```

**为什么逼视**：审判官用"你记得每个人的脸、每句话、当时的天气"这种极具体的细节指控，让用户无处可躲。三个选项覆盖了人类面对"你从未原谅"的三种真实反应。

完整样例集（S1/B2/W1/门控）见 `crucible/30-adr/c-path-full-design.md`。

## 三、维度层：通用心理维度（IP无关化）

### 为什么要改
跨IP平台要求"不同IP的角色能放在同一空间比较"。现有12维度（审判/侵蚀/羁绊/觉醒）带魔女味（"因子""侵蚀"），无法容纳小圆等其他IP的角色。

### 改法
把现有维度**抽象化**，去掉IP专属命名，保留心理测量的本质。

| 现维度（魔女味） | → | 通用心理维度 | 测的是什么 |
|---|---|---|---|
| S1 严厉度 | → | 严厉/宽容倾向 | 对他人过错的反应 |
| S2 直觉度 | → | 直觉/理性倾向 | 决策依据 |
| S3 宽恕度 | → | 宽恕/惩戒倾向 | 面对冒犯的态度 |
| F1 复仇心 | → | 复仇/释怀倾向 | 被伤害后的反应 |
| F2 绝望度 | → | 绝望/韧性倾向 | 面对绝境的反应 |
| F3 执念度 | → | 执念/放下倾向 | 对目标的执着 |
| B1 信任度 | → | 信任/防备倾向 | 对他人的初始态度 |
| B2 背叛感 | → | 背叛敏感度 | 对背叛的反应强度 |
| B3 犠牲度 | → | 自我牺牲倾向 | 为他人付出的程度 |
| W1 压抑力 | → | 情绪压抑倾向 | 处理内心情绪的方式 |
| W2 理性力 | → | 理性维系倾向 | 用理性控制行为的程度 |
| W3 本能度 | → | 本能释放倾向 | 顺从本能的程度 |

**关键**：维度的**测量逻辑和分值不变**，只改命名和描述。加权曼哈顿距离算法可以复用。现有魔女审判角色的向量值不需要重算（它们在新维度名下数值一样）。

## 四、角色层：跨IP角色库

### 架构基础
项目已有 `src/pack` 多内容包架构雏形。扩展为：

```
src/content/packs/
  witch-trial/     ← 魔女审判（现有 13+2 角色）
    config.ts      ← 角色定义（向量用通用心理维度）
  madoka/          ← 魔法少女小圆
    config.ts
  ...其他IP...
```

### 首批接入的四个 IP（用户已定）

| 序 | IP | 原名 | 核心角色 | 备注 |
|---|---|---|---|---|
| 1 | **魔法少女小圆** | まどか☆マギカ | 鹿目圆、晓美焰、美树沙耶香、佐仓杏子、巴麻美（+剧场版渚） | 第一个接入，角色最丰富、知名度最高 |
| 2 | **魔法少女毁灭者** | 魔法少女マジカルデストロイヤーズ | 御宅英雄、安那其、BLUE、PINK | JUN INAGAWA 原案，末世废土+御宅文化革命语境 |
| 3 | **憧憬成为魔法少女** | 私にあこがれて | 柊utena、花雪/魔法鹿、三色魔法少女组 | 反套路黑喜剧，"魔法少女迷变成反派" |
| 4 | **魔法少女伊莉雅** | Fate/kaleid liner Prisma☆Illya | 伊莉雅、美游、小黑/克洛伊 | Fate 衍生 |

⚠️ **IP 版权合规**：接入商业 IP 角色涉及版权。需明确产品定位——同人二创测试（通常可接受）/ 需要声明非官方 / 或仅作为内部原型。**这是开放问题，需用户决策合规策略。**

**调性差异说明**：四个 IP 调性差异大（小圆=黑暗宿命、毁灭者=废土御宅、憧憬=反套路黑喜剧、伊莉雅=Fate衍生日常）。跨 IP 匹配时，用户可能匹配到不熟悉调性的角色——这既是传播点（"我居然是PINK？"）也可能造成陌生感。结果页需处理好"陌生角色的介绍"。

**优先级**：小圆第一个接入（角色最丰富、知名度最高）。其余按序。

⚠️ **IP 版权合规**：接入商业 IP 角色涉及版权。需明确产品定位——同人二创测试（通常可接受）/ 需要声明非官方 / 或仅作为内部原型。**这是开放问题，需用户决策合规策略。**

### 跨IP匹配的核心问题
不同IP的角色，如何放在同一个通用心理维度空间比较？

**答案**：每个IP的角色，都由人工（或内容作者）**按通用心理维度打分**，形成该角色的12维向量。比如：
- 魔女审判 HIRO：[复仇心高, 绝望中, 执念极高, 信任低, ...]
- 小圆 晓美焰：[复仇心高, 绝望高, 执念极高, 信任选择性, ...]

两个角色虽然来自不同IP，但在同一套心理维度上有可比的向量。用户的答题向量与所有IP的所有角色向量计算距离，取最近的一个。

**这是内容工作量**（每个新IP的角色都要人工标定向量），不是工程难题。算法本身（加权曼哈顿距离）零改动。

### 跨IP匹配的匹配范围策略（待定）
- **全局匹配**：用户向量 vs 所有IP所有角色，取最近 → 结果可能来自任意IP（惊喜感强，但可能用户不熟的IP）
- **限定IP匹配**：用户先选IP，或系统按熟悉度筛选 → 结果可控
- **混合**：主结果限定，彩蛋可跨IP
**建议先全局匹配**（传播点在"跨IP惊喜"），但需观察用户反馈。

## 五、结果层：跨IP审判判决（待出具体设计）

### 心理契约的转变
题目从"扮演"变成"面对"后，结果页的心理契约必须跟着变——用户刚经历深刻的自我逼视，结果页不能再是简单的"角色名片"。

### 确定的方向
- 保留角色匹配（核心卖点）
- 跨IP匹配结果是天然传播点（"我居然是晓美焰？"）
- 结果页形态：**审判判决书**风格（用审判IP语言包装结果），具体设计待出样例确认

### 待定（需后续讨论）
- 判决书的具体形态（纯文字 / 卡片 / 可分享图）
- 角色如何呈现（跨IP混搭时怎么展示"你来自XIP的Y角色"）
- 维度展示（通用心理维度怎么可视化）

## 六、配套机制（与灵魂拷问编织）

这些不解决根因，但提升体验密度，缓解"单调感"：

### 审判官批注（中途反馈，替代氛围词）
每5题（第5/10/15题后），审判官停下说几句。基于已答倾向的**行为素描**（非维度标签），三次递进：
- 第5题后（试探）：「你回答时很少犹豫。这说明……你要么很清楚自己是谁，要么很擅长让自己看起来清楚。」
- 第10题后（逼近）：「有些题你答得太快了。快到像是在回避真正去想。」
- 第15题后（审判）：「你今天交出来的答案，有些连你自己都没承认过，对吧？」

**不输出维度标签/角色/百分比**（防剧透），只输出行为描写。

### 交互变奏
- **天平题**（第8/22题）：审判官"灵魂二选一"，左右推开（复用 ease-out-expo + is-dimmed）
- **砝码题**（第14题）：审判官"你来拨这台秤"，拖拽分量分配

### 节奏编排
26题里6个非标准节点（3批注+2天平+1砝码），每5题一个"不一样"的节点，打破单调。

## 八、实现优先级建议

考虑到这是一次产品重构而非局部优化，建议分阶段：

### 阶段1：核心体验（先做，可独立验证）
1. 题目改写：现有26题全部改写为审判官灵魂拷问模式（zh-CN）
2. 维度抽象化：12维度去魔女味，改为通用心理维度命名
3. 审判官批注 + 交互变奏（天平/砝码）

→ 这一步完成后，"面对自己"的核心体验就立住了，可以先验证。

### 阶段2：跨IP扩展
4. pack架构完善：支持多IP角色库
5. **小圆角色标定 + 接入**（第一个跨IP，角色最丰富）
6. 跨IP匹配的UI/结果呈现
7. 后续IP按序接入（毁灭者→憧憬→伊莉雅）

⚠️ **阶段2前置**：需先确定 IP 版权合规策略（同人二创声明 / 内部原型 / 其他）。

### 阶段3：结果页与打磨
7. 审判判决书结果页
8. 多语言（en/ja/zh-TW）批量翻译
9. A/B 实验设施
