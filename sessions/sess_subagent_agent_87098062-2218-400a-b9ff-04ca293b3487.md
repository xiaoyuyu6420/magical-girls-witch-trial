## 八、桌面端问题点（显示不全的可能原因）

1. **`#view-result` 固定 `height:100vh` + `align-items:center`，桌面端无 `overflow-y:auto`**（行 522–528 没有 overflow；`overflow-y:auto` 仅在行 789 的移动端媒体查询里追加）。内容是单栏 max 640px、垂直堆叠很高（name+subtitle+slogan+分隔+workIntro+prosecution+softlanding+tags+3 条 posture+稀有度+隐藏+按钮+声明），一旦超过 100vh，因 flex 垂直居中 + 容器不滚动，**顶部和底部会被裁切且无法滚动**。
2. **`body` 全局 `overflow:hidden`**（行 109），超出的部分在 body 层也被截断。
3. 内层 profileRef 的滚动救火机制有条件：仅当 `needsEdgeBlur`（`scrollHeight > clientHeight + 2`）为 true 时才设 `overflowY:auto + maxHeight:100vh` + mask 渐隐；但该滚动发生在内层 640px 盒上，而裁切可能发生在 `#view-result`/body 层，且 `align-items:center` 仍会把超出的盒上下两端推出可视区。
4. **死的两栏 CSS**：`.result-layout` 被设成 `max-width:1300px; padding:5vw`（为左右分栏设计），但实际只装一个 640px 居中盒，桌面宽屏下大量横向空间闲置，内容被迫纵向堆叠变高 → 加剧第 1 条的溢出。
5. **内联样式击败响应式 CSS**（见下），导致 `.r-name` 等关键元素的媒体查询字号无效。

## 九、移动端排版问题点

1. **内联 fontSize 覆盖媒体查询**：`.r-name` 在 TSX 内联 `clamp(2.5rem,10vw,5rem)`，而 CSS 行 793（≤768px）写 `clamp(2.5rem,12vw,4.5rem)`、行 828（≤480px）写 `clamp(2rem,14vw,3.5rem)`——**内联优先级更高，这两条移动端字号规则完全不生效**。subtitle 同理（纯内联，无媒体查询兜底）。
2. **posture 行的固定宽度在窄屏吃紧**：标签 `width:130` + 轨道 `flex:1` + 百分比 `width:36`，gap 0.6rem×2；在 ≤480px 上「POSTURE A (粉饰)」130px 标签会挤压进度条，且这些是内联样式无媒体查询覆盖。`.r-desc`/softlanding/姿态分布/稀有度的小标题 `0.65rem` 在小屏也偏小。
3. **`text-align:center` 被 flex 行打断**：移动端 `.result-layout { text-align:center }` 对 posture 行、稀有度行（`display:flex`）无效，这些块在居中页面里仍左对齐，视觉上与居中的标题/标签云不齐。
4. `.r-keywords`、`.r-actions` 在移动端被显式 `justify-content:center`（行 802、804），但 prosecution/softlanding/workIntro 等正文块仍是默认左对齐（`text-align:center` 对纯文字 div 生效，但对内含 flex 的结构无效）。
5. `.btn-restart` 移动端 `align-self:center`（行 561、801），但 `.r-actions` 是 flex 容器，两个按钮在 `justify-content:center; gap:1rem` 下整体居中——按钮本身是「下划线文字链接」样式，移动端可点区域依赖 `min-height:44px`，横向并排时若宽度不够会 `flex-wrap`。
