以「死亡回溯 · 希罗」为样板，把整个系统的实现走线规划出来：

## 四层架构

```
触发传感器 → 事件总线 → 调度器 → 演出层
```

**1. 能力注册表（Spell Registry）**——每个能力一个文件，统一格式：

```ts
// spells/shiro-time-leap.ts
export const timeLeap: Spell = {
  id: 'shiro-time-leap',
  character: 'SHIRO',              // 二阶堂希罗
  triggers: [
    { kind: 'dwell', ms: 20000 },  // 行为触发：单题犹豫 20s
    { kind: 'option', values: ['rewind'] },  // 选项直触
  ],
  limit: 'oncePerRun',             // 每次测试最多演一次
  priority: 2,
  cast: (ctx) => { ... },          // 演出编排，见下
}
```

**2. 触发传感器**——答题页里埋三类钩子，全部往事件总线发消息：
- `dwell`：切题时计时，超时发事件（回溯就挂这个）
- `option`：选中带标记的选项值时发事件（如 destroy → 灭世线）
- `accum`：维度分数累计过阈值时发事件

**3. 调度器（Director）**——收到事件查注册表，执行三条克制规则：优先级排队（直触 > 行为 > 累计）、**每次测试全场上限 3 场**（多了就腻）、两场间隔至少 2 题。同时命中的不叠加，进队列。

**4. 演出层（SpellLayer）**——一个全屏 fixed overlay，演出完自清理，**永不阻塞作答**（点击穿透，答案照选）。

## 回溯这场戏的演出编排（约 100 行）

5. 淡出，继续答题

## 🤖 助手
你戳中的是这个系统最核心的矛盾：**锚定角色是答完题才发生的事，而回溯是答题中途的演出**——硬要“因为是希罗所以演回溯”就鸡生蛋了。而且你后半句更狠：回溯如果真的让你改了答案，人就变了——锚定的角色也跟着变了。

但这不是死结，是三层解法：

**一、演出不锚定“角色”，锚定“倾向”（解鸡生蛋）**

调度器永远不问“你是谁”，只问“你的实时分数在往哪偏”。每答一题，向量都在累加——随时可以算一次**当前 top-3 最像谁**，这是个流动的中间态，不需要等终审。回溯的触发条件写成“你的向量与希罗的距离进入共鸣半径”，而不是“你是希罗”。

台词的语态跟着改：不说「你是二阶堂希罗」，说的是**「有个少女的魔法，与你擦肩共振——只要用她的魔法，就能回到今天早上。」**能力在共鸣，身份在终审才宣判。这跟产品的叙事（判决只出现在结果页）完全自洽。

**二、把“回溯改变答案”做成真机制（把 bug 变成主题）**

你说的“选不同答案就变成不同的人”——**这正是原作的主题本身**：希罗回溯就是为了改写结局。所以干脆做成真的：回溯演出后，上一题重新开放，浮字提示「时间被拉回了片刻——你可以重新选择」。改了，向量重算，“当前最像”随之流动。

于是形成正反馈闭环：**你越犹豫、越想改答案 → 回溯越容易发动 → 而回溯本身就是希罗浓度的证明**。回溯不再需要提前锚定，它自己就是判定器。

**三、按能力阶位分层，高阶能力换舞台（解“因果”）**

圆的因果改写干涉的是“结局”，那她的演出对象就该是**已经确定的结果**——放在结果页：出结果后长按/停留触发「已经没有什么好怕的了」，页面被粉白光“重构”一次。她根本不需要提前锚定，因为她的能力作用于终审之后。

整理成体系就是：

| 阶位 | 能力举例 | 舞台 | 干涉对象 |
|---|---|---|---|
| 场面系 | Tiro Finale、结界 | 答题中 | 只是氛围 |
| 时间系 | 死亡回溯 | 答题中 | **过程**（可改答案） |
| 因果系 | 圆的改写 | 结果页 | **结局**本身 |

**落地顺序**：MVP 先做“共鸣式回溯”（只演出、不改答案，技术上一行不碰答题流程）→ 手感对了再开“真回溯”（需要答题组件支持回退上一题，要动 test 页状态机）→ 圆的因果改写跟结果页一起做。

这样体系就闭环了：每个角色的能力按“干涉什么”决定她出现在哪，不存在锚定悖论。这个分层你认的话，我按 MVP 先把共鸣式回溯的骨架搭起来。

## 🤖 助手
不用陀螺仪——**浮空的灵魂不是“设备倾斜”，而是“影子与物体分离”**，这纯 CSS 就能以假乱真。人对“悬浮”的视觉判断靠的是：物体和影子脱开了、运动没有落地感、碎片各自缓慢漂浮。抓住这个物理隐喻，演出就成立；陀螺仪反而是绕远路。

**汉娜·浮空的演出编排**（约 80 行，全 CSS + 少量 JS）：

1. **入戏**：所有 UI 卡片的 `box-shadow` 与本体分离拉远（影子“留在地面”）、各组元素以**错开的相位**开始缓慢正弦浮动（每块周期不同才像真悬浮，同步晃就像纸片）、背景 ghost 大字「魔女审判」缓缓上浮脱底，几粒光尘上升
2. **交互**：鼠标/手指掠过哪里，哪里的元素被轻微推开又浮回——触摸就是最好的“魔力感应”，手机桌面通吃，这就是你要的移动端答案
3. 浮字：「重力，不过是诸位共享的错觉。」（按汉娜人设从剧情里挑或仿写）
4. **落地**：三秒后一切缓缓下沉，阴影归位，最后一帧轻震一下——落地的顿挫感反过来证明刚才真的飞过

**陀螺仪为什么不进 MVP**：

- iOS 13+ 必须在用户点击手势里弹 `requestPermission()` 授权框——一次打断感极强的系统弹窗，拒绝授权后这次演出直接空转
- 桌面端没有陀螺仪，同一演出要维护两套驱动
- 页面跟随设备倾斜超过几度就容易晕、容易误触滚动

如果以后想做体感，正确的架构是把“重力来源”抽象成一个数据源：`gravitySource: 'pointer' | 'device'`，演出只消费一个重力向量。桌面用鼠标位置映射微倾斜，手机用 `deviceorientation` 的 beta/gamma 映射（±3° 内，别多）。陀螺仪从“演出前提”降格为“可选数据源”，iOS 授权失败就自动落回 pointer 模式——体系不受影响。

这也顺手定了体系的设计原则：**每个能力的具象化 = 抓它的物理隐喻，能用 CSS 隐喻解决的绝不碰传感器**。

- 回溯的隐喻 = 倒放（文字倒带、进度回抽）
- 浮空的隐喻 = 影子分离 + 相位漂浮
- 因果的隐喻 = 重写（同一段文案被另一只手改掉）
- 灭世的隐喻 = 失血（去饱和、暗红）

传感器永远只是某个能力以后的“增强包”，不是任何能力的前提。这样 24 个角色的能力库就都可以低成本铺开了。
