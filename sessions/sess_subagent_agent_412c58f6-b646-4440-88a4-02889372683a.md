## 2. 筹码分配题（weight allocator）

**存在。** 定义在 quiz-content.ts Q14（行 215–227），`renderType: "weight"`，`type: "normal"`，`dim: "F1"`。

**机制（不是点阵，是三槽 +/- 步进器）：**
- 3 个槽 A/B/C，每槽取值 `{0,1,2}`，**三槽总和必须 = 3**（TestScreen.tsx 行 430：`const isValid = total === 3`）。
- 7 个合法组合被预编码成 7 个 option，label 格式 `weight::a|b|c`：

```ts
{ label: "weight::2|1|0", score: 3 },
{ label: "weight::2|0|1", score: 3 },
{ label: "weight::1|2|0", score: 2 },
{ label: "weight::0|2|1", score: 2 },
{ label: "weight::1|0|2", score: 2 },
{ label: "weight::0|1|2", score: 2 },
{ label: "weight::1|1|1", score: 1 },
```

- score 映射规则（注释行 212–213）：主槽（值=2）在 A（"记得多深"）→ score 3（最强 F1）；主槽在 B/C → score 2（中 F1）；均匀 `1|1|1` → score 1（最弱 F1）。全部累加到 **F1 维度**。三槽主题文案从 `question.text` 解析（`A：「...」\nB：「...」\nC：「...」`，见 `parseSlotThemes` 行 43–55）。

**渲染与交互**（TestScreen.tsx 行 426–556，`renderWeightUI`）：
- 用 inline-style 画三个并排卡片，每个卡片有标题（A/B/C）、斜体主题文案、大数字（当前槽值）、`−` / `+` 按钮（行 484–517，`adjustSlot` 行 432–440，单槽范围 0–2）。
- 底部状态行：合法时显示"天平已定"（金色），否则"尚余 N 枚砝码未放"（红色）。
- 确认按钮文字"落锤"（行 550），`handleWeightConfirm`（行 283–292）把当前 `[a,b,c]` 拼成 `weight::a|b|c` 去 `current.options.find(o => o.label === targetLabel)`，找到后调用通用的 `handleSelect`。

## 4. 评分逻辑

核心文件：
- `/Users/munich/Desktop/独立项目/magical-girls/src/lib/answer-processor.ts`（聚合原始分）
- `/Users/munich/Desktop/独立项目/magical-girls/src/lib/match.ts`（向量构建 + 匹配）

**流程（无 postureA/B/C；按 12 维度累加）：**

**Step A — 聚合（answer-processor.ts `processAnswers`，行 21–65）：**
服务端从 DB 重新派生，不信任客户端。遍历答案：
- 若 `question.type === "gate"`：读 `option.value`，命中 `gateValues` 集合则设 `gateValue`，**continue（不计分）**。
- 若 `question.type === "trigger"`：读 `option.trigger` 设 `triggerFired`，**continue（不计分）**。
- 否则：`dimScores[dim] += option.score`（dim 跳过 `"GATE"`/`"TRIGGER"`）。scale/weight 题的 `type` 是 `normal`，所以走这条——它们的 score（1/3 或 1/2/3）照常累加进对应 dim（W2 / F1）。

**Step B — 门控加分（match.ts `applyGateBonus`，行 120–133）：**
```
peace     → S2 +1
undecided → W1 +1
```
每维上限封顶 6。destroy/seen 没有额外加分。

**Step C — 原始分 → 档位（match.ts `buildUserValues` 行 135–141 + `scoreToTier` 行 44–49）：**
对每个维度，原始总分按 `ALGO_CONFIG.tiers`（config.ts 行 28–33）转档位值 0–3：
- `≤2 → L (0)`
- `≤4 → M (1)`
- `≤5 → H (2)`
- `≤6 → X (3)`

得到长度 12 的用户向量，`formatVector` 按 3 个一组拼成 `"LHH-LLM-HHH-LLL"` 形式。

**Step D — 特殊字段如何影响结果：**
- **gateValue**：① Step B 加分；② 与 triggerFired 一起参与特殊人格解析。
- **triggerFired**（`SPECIAL_A` 等）：见 `resolveSpecialCode`（match.ts 行 143–170）。优先查 pack 的 `specialTriggers` 映射表（`/Users/munich/Desktop/独立项目/magical-girls/src/content/packs/witch-trial/index.ts` 行 25–30）：

```ts
specialTriggers: {
  SPECIAL_A: { destroy: "YUKI", seen: "ETL" },
  SPECIAL_B: { destroy: "ETL", seen: "YUKI" },
  YUKI: { destroy: "YUKI", seen: "YUKI" },
  ETL: { destroy: "ETL", seen: "ETL" },
},
```

即 `SPECIAL_A + destroy → YUKI`（月代雪/大魔女），`SPECIAL_A + seen → ETL`（不灭雪华/梅露露真身）。这是唯一的"特殊结果解锁"机制，**不存在 keyUnlocked 字段**。

## 5. 结果匹配

**核心文件 `/Users/munich/Desktop/独立项目/magical-girls/src/lib/match.ts`，主函数 `match()`（行 172–323）。** 调用方 `/Users/munich/Desktop/独立项目/magical-girls/src/app/api/match/route.ts`（行 52）。

匹配四步：

**① 特殊触发（行 192–226）：** 若 `triggerFired && gateValue`，`resolveSpecialCode` 解析出特殊人格码（YUKI/ETL）。命中则直接返回，`similarity: 100`，`group: "special"`，`special: true`，跳过向量匹配。

**② 用户向量（行 228–231）：** Step B/C 得到 `userValues`（12 维档位数组）和格式化字符串。

**③ 向量匹配（行 233–242）：** 对所有 `!special && group !== "fallback"` 的常规人格（13 个，EMMA/SHERRY/.../LEIA），用 `weightedManhattan`（行 52–63）算用户向量与该角色 `vector` 模板的**加权曼哈顿距离**，权重来自 pack `weights`（config.ts 行 20–25；S1/F1/B3/W3 权重 1.5，其余 1.0）。`similarity = round((1 - dist/maxDist) * 100, 1)`（行 71–75），`maxDist = Σ(weight_i × 3)`。按距离升序排，取 top3，best = top3[0]。

**④ 边界检查（行 264–299）：**
- `delta = 3`，`threshold = 40`（config.ts 行 34–35）。
- 若 `best.sim - top3[1].sim < delta`（top1/2 太接近）：
  - 且 `best.sim < threshold` → 返回兜底人格 **UNSET**（`group: "fallback"`，`borderType: true`）。
  - 否则 → 正常返回 best 但 `borderType: true`（标记边界型）。
- 无候选则返回 UNSET。

兜底人格 UNSET 向量 `"MMM-MMM-MMM-MMM"`（quiz-content.ts 行 88）。`PersonalityTypeDef` 含 `code/name/group/vector/slogan/desc/keywords/special`，DB 里还有 `ipCode`（角色 IP 归属，witch-trial 或 madoka，支持跨 IP 匹配，schema.prisma 行 60–62）。
