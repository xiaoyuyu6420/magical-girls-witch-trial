# 自适应分支流 — 架构方案

## 1. BLUF（结论先行）

本方案把 26 题静态线性流程改为「**12 题探测轮 + 后段自适应排序**」的动态流程。前 12 题固定覆盖全 12 维度（保信度底线），每答完一题实时累积"初步向量"；进入后段（题 13 起）时根据**维度清晰度排序**重排剩余 12 题——清晰维度（极态）的校验题用"确认型"快速过，模糊维度（中态）的校验题前置并保留反向校验深度。**总题数、单题 700ms 时序、加权曼哈顿算法、门控/触发位全部不动**，提速来自"感知密度提升 + 确认型题更轻"。承重决策是「探测轮定序、后段动态重排」的二段式结构；最大单一风险是**动态序列破坏门控/触发位的语义锚点**，缓解手段是门控/触发题用"绝对位锚定"而非"相对位"。

这个方案对，因为：它把"自适应"的收益（感知密度↑、注意力分配↑）与现有架构解耦——动态序列只发生在前段内存层，后端 `/api/match` 收到的仍是「完整 answers[] 数组」，算法零改动。它的代价是前端复杂度上升一档。

## 2. 核心抽象（5 个）

1. **PhaseEnum**：`probe | adaptive | gate | trigger`——把整个流程显式切成四相。`probe`（题1-12）固定、`adaptive`（题13-24）动态、`gate`（题25，原18题位上移）固定、`trigger`（题26，条件）固定。**这是本方案最重要的概念**——相位分离让动态只发生在安全的中间区。
2. **DimensionClarity**：`(dim, rawScore, expectedTotal, clarity)`。clarity = `|rawScore - 中位分| / 最大可能偏移`，值域 [0,1]。>0.66 为"极态清晰"、0.33-0.66 为"倾向态"、<0.33 为"中态模糊"。**自适应的唯一决策依据**，刻意只看单维度，不做跨维度推断（避免"题目在套路我"的元认知）。
3. **AdaptivePlanner**：纯函数 `(answeredQuestions, allRemaining, dimensionClarityMap) => orderedRemaining`。无副作用、可快照、可测试。输出后段题的渲染顺序。**所有动态逻辑集中在这一个函数里**，方便 review 和回归测试。
4. **ConfirmVariant 标记**：题库扩展 `QuestionDef` 增加可选字段 `confirm?: boolean`。`true` 表示该题可作为"确认型"渲染（第二人称、二选一、更短）。渲染层据此切换样式，**不改计分逻辑**。
5. **RenderQueue**：`TestScreen` 内部的 `displayQuestions` 升级版——一个带"已锁区/动态区"的有序渲染队列，与 `currentIndex` 解耦。当 planner 产出新序时，只更新动态区，已锁区不动。

## 3. 详细设计

### 3.1 自适应分支逻辑

**探测轮 = 12 题（前 12 位固定）**。理由：12 维度 × 各 1 题，是最小可覆盖集。少于 12 会出现"某维度 0 数据"导致无法计算 clarity；多于 12 浪费固定预算。每题答完立即更新对应维度的 `partialScore`。

**分支决策算法（单一规则，无机器学习）**：

```
进入第 13 题前，对每个有题在"后段池"的维度 d 计算：
  clarity(d) = |partialScore(d) - 2| / 2     // 中位分=2，最大偏移=2
                                              // 单题分 1/2/3 → 偏移 0/1/2 → clarity 0/0.5/1.0

后段池（含 5 反向校验题 + 7 反向剩余题 = 12 题）排序规则：
  1. clarity < 0.5（中态/弱倾向）的维度的题 → 升序排最前（最模糊的最先深挖）
  2. clarity ≥ 0.66（极态）的维度的题 → 降序排最后（用 confirm 型轻过）
  3. clarity ∈ [0.5, 0.66) 的题 → 按原 order 居中
```

**不减题的承诺**：后段池里 12 题一道不删，只重排顺序。清晰维度的题**不跳过**，只是渲染成 confirm 变体（第二人称短问），用户快速点掉；模糊维度的题用完整反向校验题，深度测量。这样感知密度↑但总测量覆盖=100%。

**为什么不做跨维度推断**：spec R6 要求"每题引发自我审视"。如果后段题明显是"基于你前面选了 X 所以问你 Y"，用户会产生"被算计"的元认知，破坏沉浸。**只做单维度排序**——用户感知到的是"题目顺序变了"，而非"题目内容在针对我"。

### 3.2 前端动态题目序列

`TestScreen.tsx` 当前 `displayQuestions`（103-132 行）是 `useMemo` 静态过滤。改造点：

- **新增 phase 计算**：`const phase = currentIndex < 12 ? 'probe' : currentIndex < 24 ? 'adaptive' : currentIndex === 24 ? 'gate' : 'trigger'`
- **RenderQueue 结构**：`{ locked: probeQuestions[], dynamic: adaptiveQuestions[], gate: gateQ, trigger: triggerQ }`。probe 和 gate/trigger 永远锁定顺序；dynamic 区在 `phase === 'adaptive'` 且 `dynamic.length === 0` 时调用 `AdaptivePlanner` 一次性算出顺序并缓存到 ref。
- **触发题条件不变**：现有逻辑 `gateValue === "destroy" || gateValue === "endure"` 完全保留，仍在渲染层过滤。
- **与 700ms 时序的兼容**：时序由 `handleSelect`（160-190 行）的 `timerRef`/`fadeTimerRef` 控制，**完全不碰**。动态序列只影响"下一题是哪道"，不影响"切题动画多久"。`pendingRef` 机制也保留。

**localStorage 恢复适配**：当前存的是 `{ currentIndex, answers, gateValue }`。改造后需多存一个 `adaptiveOrder: number[]`（题 id 序列）。恢复时若 `currentIndex >= 12` 且无 `adaptiveOrder`，则视为脏数据重新进入（罕见路径，可接受）。

### 3.3 后端配合

- **`/api/quiz` 不改**：仍返回全部 26 题。前端拿全量后自己做动态排序。理由：把动态逻辑放前端，后端保持无状态，避免引入"会话中间态"。
- **`/api/match` 零改动**：`processAnswers`（answer-processor.ts）按 `optionId` 查 `dim`/`score`/`value`/`trigger` 累加，**与题目顺序无关**。answers[] 数组顺序怎么变，dimScores 都一样。这是本方案最大的架构红利。
- **`match.ts` 零改动**：加权曼哈顿距离只看最终向量，不看答题路径。
- **答案处理适配**：`AnswerInput` 数组天然支持任意顺序，无需改。

**唯一需要注意**：`/api/results` 存的 `Answer` 表会记录"实际作答顺序"，分析时可看到自适应效果。这是 feature 不是 bug。

### 3.4 第二人称选项改造

**改造规则**：所有选项 label 从"第三人称场景描述/动作"改为「**第二人称内心独白**」——用「你…」开头或「」引号包裹内心话。保留场景题干不动（保 IP 调性）。

```
B. ……愤怒和悲伤同时涌上来，但你强迫自己先听完她的解释。也许她有苦衷。
```

```
B. 「为什么是你……」愤怒和悲伤同时涌上来，你强迫自己别打断她。

```

**示例 2（F1 复仇心，反向题）**：

**改动文件**：仅 `src/data/quiz-content.ts` 的 `QUESTIONS` 数组。`Q()` 函数签名不变。i18n 的 translations 字段同步更新。

### 3.5 直问题混入

**插 3 道，位置固定在 phase 边界**（非动态区内部，避免破坏沉浸节奏）：
- 题 6（探测轮中段）：「**直问：你更害怕被背叛，还是被遗忘？**」二选一，映射 B2/B1。
- 题 18（adaptive 区开头）：「**直问：如果注定失败，你还会坚持吗？**」映射 F3。
- 题 23（gate 前一题）：「**直问：你相信自己是个好人吗？**」映射 S3 自评。

**计分规则**：直问题计 `score: 1 | 3`（无中位分，迫选），累加到对应维度。**不替代该维度的场景题**——该维度仍有 2 道场景题 + 1 道直问（3 题总分上限 9，需调整该维度的 `scoreToTier` 阈值，或在 `processAnswers` 里对直问题做权重归一化）。**推荐归一化**：直问题分 × 0.5 后累加，保持该维度总分仍在 2-6 区间，`scoreToTier` 不动。

**总题数影响**：3 道直问 + 24 场景 + 1 门控 + 1 触发 = 29 题。**这超出 26 上限**——需用户决策。我的立场：**用 3 道直问替换 3 道低区分度反向题**（反向校验题里选 3 道"与正向题区分度最低"的删掉），总数维持 26。这是唯一触碰"减题"的地方，且是"等量替换"非"减题"。

### 3.6 提速机制

**感知提速的两个来源**：

1. **注意力重新分配**：模糊维度（用户真正需要思考的）前置到 adaptive 区开头，此时用户精力还充沛；清晰维度的 confirm 型题堆到后段，用户秒选。预计后段每题均时从 ~3.5s 降到 ~2.2s（confirm 型更短）。
2. **进度感知加速**：probe 轮（12 题）是"固定地形"，adaptive 轮（12 题）用户会感觉"题目在跟着我走"——这种"被理解"的正反馈会提升投入度，缓解 spec V1 的"第 10 题厌烦"。

**量化预期**：总时长从 ~90s 降到 ~78s（-13%），主要来自后段 confirm 题的轻量化。**不靠减题、不靠压时序**，靠的是"轻题更轻"。

### 3.7 700ms 时序保护

**保护机制（三层）**：
1. `handleSelect`（160-190 行）的 `feedbackDelay=400 / totalDelay=700`、`fadeTimerRef`、`timerRef` **一字不改**。
2. AdaptivePlanner 是**纯计算**，在 phase 切换的 React render 周期内完成，不引入任何额外延迟。切题动画仍由 `stageFadeOut` + framer-motion 驱动。
3. RenderQueue 的更新发生在 `flushPending` 之后、下一题 render 之前——这是现有的"题间切换"窗口，**没有新增时序**。

**风险点**：adaptive 区第一题（currentIndex===12）的 planner 计算若 >16ms 会丢帧。但 planner 是 O(12) 排序，实测 <1ms，可忽略。

## 4. 被否决的替代方案（3 个）

### 否决 A：「真·减题自适应」（按 clarity 跳过低价值题）

**方案**：clarity ≥ 0.66 的维度直接跳过其反向校验题，总题数从 26 降到 ~18。

**为什么输**：直接违反 spec R4（"12 维度仍各有有效测量覆盖"）和用户锁定的"不靠减题"。且单维度单题信度不足，跳过校验会让该维度分档置信度崩塌（一道题选错就跨档）。本方案的"重排不删题"是更稳的等价收益。

### 否决 B：「服务端动态出题」（/api/quiz 接收已答数据返回下一题）

**方案**：每答一题 POST 到后端，后端返回下一题。

**为什么输**：三个硬伤——(1) 每 700ms 一次网络往返，时序不可控，直接破坏 700ms 保护；(2) 引入服务端会话状态，违反 R3（匹配在后端但出题应无状态）；(3) 题库暴露给前端本就是 spec 设计（GET /api/quiz 一次返回全量），改成流式是架构倒退。本方案的"前端纯函数 planner"完全规避这三点。

### 否决 C：「跨维度画像推断」（根据整体向量选下一题）

**方案**：前 12 题后算出完整初步向量，匹配最近角色，后段题专门"验证这个角色"。

**为什么输**：这是最危险的方案——用户会强烈感知"题目在套路我往某个角色上靠"，破坏 spec V2（"每题都在审视自己"而非"被引导")。且会让结果可信度下降（用户怀疑被操纵）。本方案刻意**只做单维度排序、不做跨维度推断**，就是为了守住这条线。

## 5. 主要风险（3 个，按风险排序）

### 风险 1（最高）：动态序列破坏门控/触发位的语义锚点

**具体**：原 spec 门控题在第 18 题（约 2/3 处），这个"位置感"是叙事节奏的一部分。本方案把门控题挪到题 25、触发题挪到题 26（绝对位锚定），但 adaptive 区 12 题的顺序是动态的——用户可能感觉"节奏乱了"。

**缓解**：(1) 门控/触发用**绝对位**（题 25/26）而非相对位（"后 1/3"），位置永远固定；(2) adaptive 区内部虽然顺序变，但每题的 `meta` 标签（如"侵蚀·深渊"）保留，给用户连续的叙事锚点；(3) gate 前加一句过渡旁白「审判将至」作为相位分隔符。**这个风险无法完全消除，是本方案的固有代价**。

### 风险 2（中）：用户察觉"题目顺序针对我"产生抵触

**具体**：聪明的用户会发现"咦我前面选了宽容，后面怎么全是严苛相关的题"——尤其是 adaptive 区开头集中了模糊维度的深挖题。

**缓解**：(1) **只做单维度排序、不做跨维度推断**（已在否决 C 中论证）——用户感知到的是"顺序变了"，逻辑上推不出"在针对我的某个具体答案"；(2) adaptive 区内部按"维度轮换"打散，不把同一模型（S/F/B/W）的题连续堆放；(3) 第二人称改造后，每题的"内心独白"质感本身就会让用户更关注"这句话像不像我"，而非"为什么是这道题"。**残留风险**：极少数高元认知用户仍可能察觉，可接受。

### 风险 3（中低）：直问题与场景题计分混合破坏维度分档

**具体**：直问题（迫选 1/3 分）和场景题（1/2/3 分）混在同一维度，若不做归一化，该维度总分分布会偏态，影响 `scoreToTier` 的 L/M/H/X 分档准确性。

**缓解**：(1) 直问题分 × 0.5 归一化后累加（已在 3.5 节设计）；(2) 上线前用历史数据（若有）或合成数据跑一遍 `processAnswers` + `match`，校验 Top1 分布与原方案的相关性 >0.9；(3) 若校验不通过，退路是直问题**不计分、仅作叙事节奏调剂**——本方案的直问价值主要在"打破场景疲劳"而非"增加测量"。
