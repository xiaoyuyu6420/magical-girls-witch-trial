# F1 金标定调：写 1 题跑通全链路预览

## 目标
把 **F1（复仇心，Q2）** 这一题写成"金标"，跑通 `yaml → sync → DB → 浏览器` 全链路，让你在 `localhost:3010` 真机看到渲染效果，确认"就是这个味"。**通过则锁定为全量重写的对照基准**；不通过则调到对为止。

## 为什么先只做 1 题（这是对上次失败的直接解药）
上次回滚根因：① 调性"人味"无法自动验证，G0–G4 全绿了还是不行；② 26 题一次性丢给 subagent，它在长批量里滑向新模板（90% 用"不对。"起手）。这次反过来：**1 题、真机、你亲眼验、锁金标**——把不可量化的"人味"变成可对照的样本，再谈展开。

## F1 文案草案（你审批这份 plan 时就能预览调性）

> yaml Q2 结构：`_dim: 🔒 F1` / `_type: 🔒 normal` / `meta: 执念·宿怨`（已存在，保留）/ options score 正序 1·2·3（F1 正向题，H=强复仇）

**题干（text）** —— 审判官断言式指控，带具体细节，含"你"，逼问收尾：
```
别装了。你嘴上说"放下了"，可你记得每一个伤害过你的人的脸，记得他们说过的每一句话，记得当时的天气。你从来没有真正原谅过任何人——对吗？
```

**三态选项（label）** —— 严格对应 score（语义已对齐：score3=理直气壮地恨=强复仇=H）：
| score | 档位 | 态 | 文案 |
|---|---|---|---|
| 1 | L·释怀 | 否认（硬） | 不对。我是真的放下了。记着，不代表没放下。 |
| 2 | M·中间 | 承认（痛） | ……你说得对。我只是假装放下了。 |
| 3 | H·复仇 | 狡辩（合理化） | 我从不假装。恨就是恨，我凭什么要原谅。 |

> 注：这题是 REDESIGN.md 你亲口确认"很有感觉"的原样例，几乎原样保留。其中"你说得对""我从不假装"这两个起手词在金标本题里用掉，后续 25 题会被起手词配额约束（避免上次"≥11 题同开头"的模板病）。

## 执行步骤

1. **写 F1 文案（我亲自写，对照 REDESIGN 金标，不委派 subagent）** —— 只填 `content/content.yaml` 里 Q2 的 `text` + 3 个 `options.label`。🔒 字段（dim/type/score）不碰，meta 保留。其他 25 题保持空。

2. **检查环境** —— 确认 `dev.db` 在、prisma client 已 generate、3010 端口是否已有 dev server（有就复用，没有再起）。

3. **跑 sync** —— `pnpm exec tsx scripts/sync-content.ts`，自动同步到 quiz-content.ts + madoka config + i18n（zh-CN）+ DB 四层。en/ja/zh-TW 的 Q2 暂留空（先看中文调性）。

4. **真机预览** —— 确保 `pnpm run dev` 在跑，你在浏览器 `localhost:3010/test` 走到第 2 题（F1），界面切中文，看真实渲染：审判官指控的压迫感、三态选项的区分度、点击交互的手感。

5. **你验收 → 锁金标 / 调整**
   - **通过**：F1 锁为全量对照基准。然后我们讨论全量重写的展开策略（是否启动 crucible、起手词配额机制、角色文案、四语言顺序）。
   - **不通过**：你告诉我哪里不对（太狠 / 太淡 / 太戏腔 / 不像逼问 / 细节不够具体），我调 F1 再预览，循环到对。

## 明确不做的事（边界）
- ❌ 不写其他 25 题（定调阶段聚焦 1 题）
- ❌ 不写角色文案（slogan/desc/keywords）—— 那是金标锁定后的第二步
- ❌ 不做四语言翻译 —— 先把中文立住
- ❌ 不建 crucible 目录跑流水线 —— 1 题不值得；金标锁定后全量重写再用 crucible
- ❌ 不跑 verify-rewrite 的 G1 统计闸 —— 1 题统计无意义，只跑 sync
