# 手机版测试页动画重做

## 意图契约

### 目标
删掉手机版测试页当前那套"乱掉+卡顿"的动画（flex transition + 多目标 `:has` 题区压缩），保留用户认可的静态排版，重新设计一套**挤压戏剧感 + GPU 友好不卡**的移动端动画。

### 完成判定
- iPhone 真机上选择答案**不卡**（无逐帧 reflow 的 flex/height transition）
- 选中项撑开变金、未选项压成细条淡出，挤压戏剧感到位
- 切题有淡出 + 新题选项错峰淡入，过渡顺滑
- 静态排版（高度链、test-header、question-stage 布局）保持不变
- 桌面端零回归（hover/staggerIn/scale 全保留）
- `tests/mobile.spec.ts` 通过；视觉基线按需更新并核对

### 范围内
- `globals.css` 移动端动画规则的删除与重写
- 新增移动端选项进场 `@keyframes`
- `tests/mobile.spec.ts` 断言微调（如有）+ 视觉基线更新

### 范围外（非目标）
- 桌面端任何动画改动
- 静态排版/布局改动（高度链、test-header 已 OK）
- TestScreen.tsx 的交互时序改动（handleSelect 的 300/650ms 触摸时序保留）
- welcome / result 页

### 决策记录
1. **选中反馈风格** → 用户选「挤压型」。技术实现采用 **flex 瞬时切换（无 transition）+ opacity/背景色 GPU 过渡遮盖**，而非纯 `transform: scaleY`。理由：transform:scaleY 不改变实际占位（会留白）、文字会变形需隐藏；flex 瞬时一次性 reflow 不卡（只占 1 帧），配合 opacity 过渡视觉等效且更优（空间真正重分配、文字可保留截断单行）。
2. **切题过渡** → 用户选「保留淡出 + 新题轻量淡入」。淡出沿用现有 `stage-fade-out`（0.16s，已轻量）；新题进场利用 `key={option.id}` 重挂载天然触发 CSS animation，错峰淡入。
3. **题区（question-stage）** → 不再压缩。删除 height/opacity transition + `:has` 目标。题区固定高度，视觉重心稳定（呼应"不要来回挪"诉求）。

## 风险
- **flex 瞬时跳变感**：一次性 reflow 占 1 帧，被 opacity 过渡遮盖，理论上无感。真机若觉跳，可给 flex 加极短 transition（0.05s）做微缓冲——这是退出 plan 后真机调试的微调项
- **视觉基线必变**：移动端动画大改导致截图变化，属预期；更新前核对
- **桌面端隔离**：新规则全在 `@media (max-width:768px)/(pointer:coarse)` 块内，pointer:fine 桌面不触发，零回归
- `mobileOptIn` 只影响 opt-block（scale/normal 题）；砝码题（weight）不渲染 opt-block，无影响
