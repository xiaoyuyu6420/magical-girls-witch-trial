# 实现计划：用 HTML「审判庭」设计重做答题 + 评分 + 结果

## 目标（一句话）
把 HTML 的整套体系移植进项目——香槟暗黑答题视觉（手机端）+ 26 题原文文案 + posture(A/B/C)/path/tendency/keyUnlocked 评分 + 5 角色匹配；桌面端保留现有动效骨架做适配；结果页保留项目视觉框架、数据换成 posture + 5 角色。

## 总体策略：移植而非重设计
HTML 本身是可运行原型，`quizData`(26题) / `characterDatabase`(5角色) / `calculateScores`+`matchCharacter`(评分) 都是现成 JS。**直接移植这套数据和逻辑**，套进项目的 React/Next 架构，不重新发明。

## 阶段 1 · 数据层 + 评分引擎重写

**1.1 题目数据 `src/data/quiz-content.ts`**
- 用 HTML 的 26 题原文替换：`question`(题干) / `meta`(如"Q1·晨光中的许愿") / `options[].text`
- 扩展 `QuestionDef` + `QuizOption`：选项加 `posture?: "A"|"B"|"C"`、`light?`、`tendency?`、`path?`、`keyUnlocked?` 字段（移植 HTML）
- 题型结构严格对应（已确认同构）：
  - Q1–Q7/Q9–Q13/Q15–Q17/Q20–Q21/Q23–Q26：3 选项 normal（带 posture/score）
  - Q8/Q22：scale 天平（2 选项，带 tendency: SACRIFICE/OBSESSION）
  - Q14：weight 筹码（3 槽点阵，HTML 的 slots：假装平静/暗中反抗/彻底放弃）
  - Q18：gate（4 选项 path: destroy/seen/peace/stray）
  - Q19：trigger（2 选项 keyUnlocked: true/false）
- 废弃旧的 dim(12维度)/score 单维梯度逻辑（保留字段名兼容，但语义切到 posture）

**1.2 角色库 `PERSONALITY_TYPES`**
- 换成 HTML 的 5 角色：晓美焰(homura_devil) / 鹿目圆(madoka_god) / 美树沙耶香(sayaka_siren) / 佐仓杏子(kyoko_pragmatist) / 樱羽艾玛(emma_truth)
- 每角色字段：name / ip / tags / prosecution(审判官逼视) / softlanding(温柔落点) / check 匹配函数（移植 HTML 的 characterDatabase）
- 兜底角色用 emma_truth（HTML 里 check 返回 true 的默认项）

**1.3 评分引擎 `src/lib/answer-processor.ts` + `src/lib/match.ts`**
- `answer-processor`：聚合 postureA/B/C 总分 + q18_path + q19_keyUnlocked + tendency（移植 HTML 的 `calculateScores`）
- `match`：移植 HTML 的 `matchCharacter`——遍历 5 角色的 check 函数，命中返回，否则兜底 emma
- 旧的 12 维向量/加权曼哈顿/分档逻辑全部移除

**1.4 pack 机制 `src/content/packs/witch-trial/`**
- witch-trial pack 的 dimensions/weights/algo 不再适用 posture 体系；**简化或旁路**——评分直接用 match.ts 的 posture 逻辑，pack 只保留元信息（标题、作品介绍）
- 小圆角色 pack (`madoka/config.ts`) 与 HTML 的 5 角色对齐合并

**1.5 DB schema `prisma/schema.prisma` + `seed.ts`**
- `Option` 加 `posture String?` 列；`Question` 的 path/tendency/keyUnlocked 复用现有 `value`/`trigger` 列或新增
- `PersonalityType` 表换 5 角色（vector 列废弃或留空，加 prosecution/softlanding/tags 列）
- 重写 seed 灌入新数据
- **风险**：schema 改动需 prisma migrate，现有 dev.db 数据会重置（可接受，开发库）

**1.6 API `src/app/api/quiz/route.ts` + `api/match/route.ts`**
- quiz route：透传 posture/path/tendency 等新字段
- match route：调用重写后的 posture 评分

**验证**：`pnpm vitest run`（scores.test 要重写适配 posture）；`curl /api/quiz` 看新字段；手算一组答案验证匹配

## 阶段 2 · 答题页视觉（手机端香槟暗黑 + 桌面适配 + 天平 + 筹码）

**2.1 设计 token + 字体 `src/app/globals.css` + `layout.tsx`**
- globals.css 新增香槟色变量（手机端作用域）：`--champagne-main:#d8c8b0` / `--champagne-light` / `--champagne-dim` / `--card-glass` / `--border-muted`
- layout.tsx 用 `next/font/google` 加载 **Syne**（HTML 的 display 字体），挂 `--font-syne`；手机端答题页用 Syne + Noto Serif SC + Cinzel

**2.2 手机端香槟风（`@media (max-width:768px), (pointer:coarse)` 作用域）**
还原 HTML 的答题页：
- **HUD 胶囊顶栏**：blur 玻璃态胶囊（返回 + 题号计数 + 重启），替换现有 test-header
- **顶部进度条**：细香槟色线（保留现有 #progress-line 结构，改色）
- **题卡**：玻璃态卡片（backdrop-blur、圆角 20px、border-muted）+ fadeIn/fadeOut 切卡动画
- **meta-tag**（Q1·晨光中的许愿）+ **toast-verdict**（✦ 契约已被记录 ✦，选中后闪现 400ms）
- **普通选项**：opt-item（序号方块 opt-key + 文案），hover/selected 香槟金边
- **grain 噪点层** + **巨型水印数字**（bg-watermark，题号）加到 TestScreen 内部（注意：答题页在 /test iframe 内，不是宿主页）
- **背景 canvas**：HTML 有微光 canvas，可移植或用 CSS 静态背景替代（性能权衡，倾向 CSS 静态 + grain）

**2.3 桌面端适配（最小改动，保留你喜欢的动效）**
- 保留现有 `.opt-block` hover 挤压（flex:1.8→8）、staggerIn 入场、金色审判官配色
- 普通题：只换文案（阶段 1 已换），视觉不动
- 天平/筹码：用桌面金色 token 实现新样式（见 2.4/2.5 的桌面版）

**2.4 天平题（Q8/Q22）真实倾斜 — 全端**
- 新建天平视觉：左右两个托盘 + 中间支点 + 横梁
- 交互：点托盘 → 该侧下沉（rotate + translateY）、另侧上翘、香槟/金色光晕 → 沿用现有 handleSelect 时序自动进下一题
- 手机端：香槟色、竖向紧凑布局；桌面端：金色、横向展开
- 键盘 1=左 2=右（沿用）
- **绕过**普通题的挤压动效（天平用专属布局）

**2.5 筹码题（Q14）点阵点击 — 全端**
- 把现有 `renderWeightUI` 的 +/- 步进器换成 HTML 的点阵：3 个槽各 3 个圆点（node-dot），点亮点亮/熄灭，总和=3 才能落锤
- 沿用现有 `adjustSlot`/`handleWeightConfirm`/`weight::` 编码逻辑（只换 UI 层）
- 手机端香槟点阵、桌面端金色点阵
- 槽主题文案用 HTML 的（假装平静/暗中反抗/彻底放弃），通过 question.text 解析（沿用 parseSlotThemes 或改格式）

**验证**：手机端真机/模拟器看香槟风；桌面端看动效保留；天平倾斜/筹码点阵交互；`pnpm playwright test tests/mobile.spec.ts`

## 关键风险
1. **工作量大**：≈ 重写项目核心（评分/角色/视觉/结果），预计多轮实施。建议按阶段交付验收（先阶段 1+2 跑通答题，再 3+4）
2. **posture 评分迁移**：直接移植 HTML 的 calculateScores/matchCharacter，已是验证过的逻辑，风险低；但接入项目 API/DB 链路需仔细
3. **两套视觉并存**：手机香槟 + 桌面金色，天平/筹码要写两套配色，工作量翻倍
4. **DB schema 改动**：prisma migrate 会重置 dev.db（开发库可接受）
5. **测试全要改**：现有 E2E 依赖旧 DOM/旧 meta，需同步更新
